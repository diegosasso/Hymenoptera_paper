HAIKA versus ontophylo wing-rate comparison: independent methods review
2026-11-20

Scope and immediate recommendation
----------------------------------
The comparison is feasible as an exploratory comparison of relative evolutionary
patterns. It is not a direct comparison of absolute rates or a validation of the
same morphological measurements. The paper uses standardized forewing line
drawings emphasizing outline and primary venation. The final ontophylo character
audit identifies nine fore-wing characters: seven vein/stigma characters
(CH353-CH359), one nygmata character (CH360), and one muscle character (CH294).
There is substantial overlap in forewing venation. The main differences are
discrete character states versus image geometry/learned continuous features,
the extra muscle character, and family-proxy versus morphology-exemplar data.
The source category "sclerite" is a broad ontology annotation here; it does not
mean these eight characters are principally wing-base sclerites. The filename
fore_wing_sclerites denotes the eight-character vein/stigma/nygmata sensitivity.

Practical first analysis: fit the published HAIKA PC1 and PC2 scores separately
using phytools::multirateBM on the matched subtree of the existing dated tree.
Use lambda = 0.1, 1, 10 as a prespecified penalty sensitivity grid, alongside a
homogeneous-BM baseline. Do not select the penalty that maximizes agreement with
ontophylo. Keep PC1 and PC2 results separate. Compare to ontophylo fore-wing
rates first, with all-wing and hind-wing outputs explicitly secondary.

For an eventual joint analysis, a shared branch multiplier multivariate BM model
is preferable to averaging independently estimated PC rate surfaces. RevBayes
provides an existing implementation. Lack of an installed RevBayes executable
does not prevent completing the univariate pilot and data audit.

What the publication measures
-----------------------------
Peng et al. report a continuous learned representation, and use PCA for Case 3.
Their first two PCs explain 74.5% of variance (42.5% and 32.0%). The paper links
PC1 primarily to wing shape and PC2 to venation complexity, while acknowledging
overlap. These are empirical associations, not one-to-one character homologies.
The supplementary attention assessment is a qualitative plausibility check.

The published branch/node delta values are absolute differences between fastAnc
ancestral estimates. They are not divided by elapsed time and are not estimates
of a branch-specific BM variance rate. They must not be reused as rates. A fresh
BM fit on the requested tree is necessary.

The architecture and methods describe 64 latent dimensions, whereas the data
audit currently reports 28 numeric feature columns in the released Case 3
workbook. Preserve this discrepancy in provenance and use the actual released
data dimensions; do not silently pad or describe the matrix as 64-dimensional.

The extraction audit additionally found that the 169 Case 3 rows contain only
105 unique complete 28-dimensional profiles; the 169 published PC1/PC2 pairs
contain only 71 unique pairs. The Case 2 continuous matrix has 61 taxa but only
26 unique 64-dimensional profiles. These are exact duplicates in the released
values, not established biological replicates. They can reflect rounding,
shared images/proxies or preprocessing, and the source cannot be inferred from
duplication alone. Audit which matched tips share profiles and avoid assuming
169 independently measured wings. Perfectly identical close relatives can drive
BM rates toward small bounds; report this diagnostic explicitly.

Data and taxon harmonization
---------------------------
1. Preserve the dated 77-tip tree exactly as the master coordinate system. Save
   branch identity using descendant-tip sets, not integer node IDs alone.
2. Construct one audit table with operational tree label, molecular source taxon,
   ontophylo morphological source taxon, HAIKA image/source taxon, original
   spelling, accepted spelling if explicitly verified, and match category.
3. The ontophylo audit reports 22 molecular-versus-morphology genus substitutions.
   A label match to the molecular tip is consequently not automatically a match
   to the morphological organism. Prefer matches to the actual morphological
   organism and explicitly retain the inherited phylogenetic proxy status.
4. Primary biological matching should use identical species when available.
   Genus-only or family substitutions must be separate sensitivities. Do not use
   ontophylo states or its reconstructed rates to choose or impute HAIKA values.
5. Fit on the induced subtree of observed matched taxa. A missing-tip BM model
   does not create data support for unobserved terminal branches. Drawing a full
   77-tip rate map with missing taxa would require identifying prior-driven
   branches and should not be the primary result.
6. If more than one image/specimen is available per species, aggregate within
   species before phylogenetic analysis and estimate measurement variance where
   replication permits. Independent images are not independent phylogenetic tips.
7. Keep Case 2 and Case 3 embeddings separate unless identical encoder weights,
   preprocessing and coordinate systems are demonstrated. Similar column labels
   do not establish shared feature coordinates.

Pruning and comparison on the same branches
-----------------------------------------
Pruning can collapse several original edges into one observed edge. For rate r_i
and duration l_i, preserve the integrated amount A = sum_i(r_i*l_i), then use
r_collapsed = A/sum_i(l_i). Never average rates without duration weights and
never copy the rate from just the surviving descendant edge.

Applying this transformation to existing full-tree ontophylo rate draws gives
a comparison conditional on the original reconstruction. Reconstructing the
discrete data anew on the matched subtree is a distinct sensitivity analysis;
it can reveal how missing taxa change inference. Label these two operations
separately. Marginal curves must use the same retained branches and age limits.

Implementation trap in phytools::multirateBM
------------------------------------------
Verified by reading local phytools 2.5.2 function bodies on 2026-11-20:

* fit$sig2 has Ntip + Nnode entries. These are NODE rates, not a vector of
  edge-average rates.
* The likelihood rescales edge e=(p,c) by its duration times the logarithmic mean
  of the parent and child rates. For d = log(r_c/r_p),

      r_edge = r_p * expm1(d) / d,

  with limit r_p when d approaches zero. The function phytools:::ln.mean uses
  the mathematically equivalent formula. Exporting fit$sig2[child] as an edge
  rate is incorrect.
* Internally this corresponds to log-linear rate interpolation along an edge.
* method="REML" is not implemented and is changed to ML. Record ML accurately.
* The optimizer retries until convergence; the n.iter argument is a minimum,
  not a guaranteed maximum number of attempts. Apply scheduler wall times and
  record convergence and bound proximity.
* fit$k is a nominal parameter count. Ordinary AIC using that count is not a
  justified method to choose the smoothing penalty/effective complexity.
* Lambda sets a cost for log-rate variation; numerical time units affect the
  penalty. Keep branch-length units fixed across all analyses and simulations.

Implementation delivered in scripts/bm-model.R: fit_bm_bounded uses the exact
installed phytools log_lik objective with the package's default parameter bounds,
a fixed number of independent optimizer starts, and explicit failure reports.
Its first start is the package's constant-PIC initialization; additional starts
add reproducible N(0,0.5^2) perturbations on the log-rate scale. Numerical edge
rates use the stable logarithmic-mean formula. A separate covariance-based
likelihood calculation checks that the exported edge rates reproduce the fit.
A six-tip simulated smoke test found an identical first-start objective to the
public phytools multirateBM function, branch means agreeing to 1.1e-15, and an
identical constant-BM maximum likelihood. This verifies implementation on the
test case, not statistical calibration or adequate fitting of the actual data.

For each retained dataset/axis/penalty, record objective, convergence code,
number of available tips, range of rates, bound hits, tree height and package
version. Large changes across penalties are scientific uncertainty, not merely
an optimization nuisance.

Marginalization through time
---------------------------
Define a time bin k by age interval [a_k,b_k] and let L_ik be the duration of
edge i that overlaps that bin. For branch-average rates, the comparable marginal
lineage rate is

      R_k = sum_i(r_i * L_ik) / sum_i(L_ik).

The denominator is lineage-time exposure, not bin width, number of nodes, or
the number of tips. At an instant, the analogous expression is the arithmetic
mean across lineages present at that instant. Compute the transformation for
each reconstruction or posterior draw first, then summarize draws.

If a phytools fitted within-edge curve is required, integrate its log-linear
rate rather than using the constant edge average. With edge duration l,
d=log(r_c/r_p), and distances s0 and s1 from the parent,

      integral = r_p*l/d * [exp(d*s1/l) - exp(d*s0/l)].

Use the constant-rate limit when d is near zero. The full-edge integral equals
l*r_edge. A primary comparison using constant edge averages is legitimate if
labeled "branch-aggregated marginal rates"; an exact interpolation curve is a
model-based sensitivity. Neither supports locating events more precisely than
the branch information allows. Report branch/lineage exposure alongside curves.

Scale and dimension choices
---------------------------
Ontophylo rates count reconstructed discrete changes per time (with any package
normalization verified by the audit); BM sigma-squared measures trait variance
per time. Their absolute values and units cannot be equated.

For every dataset/draw, normalize by the same tree-exposure-weighted mean:

      r_bar = sum_i(r_i*l_i)/sum_i(l_i),   relative_r_i = r_i/r_bar.

Apply this before summarizing uncertainty or calculating normalized curves.
Retain raw values with units in the output tables. A relative rate of 2 means
twice that representation's own mean, not equal morphological change across
representations. Spearman branch association is scale invariant.

For PC1/PC2, retain published scores and scaling for the replication-oriented
analysis. Multiplying one axis by c multiplies BM variance rates by c^2, so raw
PC rate ratios depend on the chosen trait scale. Ordinary PCA produces sample-
uncorrelated scores, not independent evolutionary histories or independent
phylogenetic contrasts. Analyze each axis separately in the pilot.

For full released features, a covariance-based PCA (centering, without feature
standardization) preserves the released Euclidean geometry. A correlation-PCA
is a separate metric giving low-variance dimensions greater influence. Do not
whiten all retained PCs by default: it changes the biological metric and can
amplify small noisy dimensions. Retention of 2 PCs, sufficient PCs for 90/95%
variance, and a capped modest dimension are useful prespecified sensitivities.
PCA across all released taxa preserves published embedding geometry; PCA on
matched taxa answers a different, sample-conditional question. Report the choice.
Never pool PCA axes estimated in different runs without an explicit alignment.

Multivariate model for a later joint analysis
--------------------------------------------
A tractable model is

      delta X_i ~ MVN(0, l_i * q_i * Sigma),

where q_i is a scalar branch multiplier and Sigma is shared across branches.
Constrain the scale of Sigma (or q) to avoid multiplicative nonidentifiability.
RevBayes separates average rate, relative character variances, and a correlation
matrix. Its official tutorial uses

  dnPhyloMultivariateBrownianREML(tree,
      branchRates=branch_rates^0.5, rateMatrix=V)

and provides a random-local-clock model for branch multipliers. The square root
is essential because this argument takes a standard-deviation scale.

The HTML tutorial has apparent variable-name inconsistencies (`beta_root` and
`background_rates`); use a verified accompanying script and validate simulated
constant-rate recovery, not a literal copy of that HTML snippet. Estimate a
modest number of PC dimensions with shrinkage on correlations, and compare a
diagonal covariance sensitivity. Do not estimate a separate full covariance
matrix on each branch of this small tree.

Independent branch rates are weakly informed when there is one observed value
per tip. Shrinkage, rate-shift priors or smoothness penalties are essential.
Under BM REML with an unknown root mean, the two basal variance contributions
are identified only through their sum (the BM pulley principle). A rooted rate
prior can allocate that sum but does not create independent basal information.
For branch comparisons, flag the basal pair and include a sensitivity excluding
them; merge their integrated variance if presenting identifiable unrooted edges.

Association and null comparisons
-------------------------------
Primary descriptive summaries:
* Spearman association across matched branch rates, separately for PC1 and PC2.
* Association separately for internal and terminal edges, with basal sensitivity.
* Rate-versus-duration and rate-versus-depth plots to reveal geometry effects.
* Concordance of predeclared high-rate branches or clades, with uncertainty.
* Matched, normalized marginal curves and broad-interval contrasts.

Do not report ordinary cor.test P values as if branches or adjacent time bins
were independent observations. Do not choose smoothing, PC retention, taxon
substitution or time bins to maximize agreement.

A practical topology/geometry check is a parametric homogeneous-BM null: simulate
tip data under a fitted constant BM on the exact matched tree, refit the same
multirateBM penalty, and compare the resulting branch correlation with the fixed
ontophylo vector. Repeat the whole normalization and marginalization pipeline.
This measures whether shared tree geometry plus rate-estimation behavior can
produce the observed agreement under homogeneous HAIKA evolution. It is NOT a
general null of independence between two heterogeneous evolutionary histories.

For a stronger independence test, independently simulate a heterogeneous HAIKA
rate field with prespecified/estimated smoothness, then tip data and full refits,
while leaving ontophylo conditional. Match plausible marginal rate variation and
time trends and use sensitivity across rate-field assumptions. A fully joint
null would simulate and reconstruct both data types, which is much more work.
Simple arbitrary branch permutations destroy phylogenetic rate dependence and
are not valid replacements. A length/depth-stratified permutation is at most
an explicitly heuristic sensitivity, not an exact test.

For a quick Roihu stage, start with 20-50 simulated refits to estimate runtime
and failure rate, then scale to at least 199/499 for a coarse calibrated tail
probability if warranted. Record all failures rather than selecting successful
simulations after observing their correlations. A simulation-derived tail area
must be named for the null actually simulated, not presented as a universal
test of concordance.

Uncertainty and claims
----------------------
Propagate available ontophylo map/reconstruction samples through collapsing,
normalization and marginalization. Across-map quantiles are reconstruction
intervals, not repeated-sampling confidence intervals. A single penalized BM
fit has no posterior distribution: a penalty range is sensitivity, not a 95%
confidence band. Parametric refits under the fitted model can supply conditional
bootstrap uncertainty if computationally feasible, subject to shrinkage bias.

Without replicated images, seed-specific released embeddings, or retraining,
HAIKA inference is conditional on one learned representation and preprocessing.
Feature bootstrap columns are not independent character replicates. Neither
phylogenetic uncertainty nor ANN uncertainty is covered by a fit on one fixed
tree and one matrix. These limits matter when interpreting precise branch ranks.

Expected deliverables
---------------------
Auditable taxon crosswalk; source hashes; exact matched tree(s); input score and
feature matrices; onto and HAIKA branch rates; rate-to-branch conversion checks;
common-exposure marginal curves; penalty/dimension/taxon sensitivity tables;
pilot null/diagnostic results; editable plots; and a concise report distinguishing
observed agreement, geometry effects, and anatomical-scope limitations.
